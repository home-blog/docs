# Research: 글결 MCP (020)

> 2026-10-20, 사용자 "알아서, 색다르게" 범위에서 추천안으로 정한 가안이다.

### D-1. MCP 서버를 무엇으로 — **가안: 우리가 짠 작은 JSON-RPC 처리기(stateless Streamable HTTP)**
- A Spring AI MCP 서버 starter(2.0.1): 도구 등록이 쉽다. 그러나 2.0.1은 Boot 4.0 기준이고(우리는 4.1), 요청마다 회원을 아는 방법(보안 문맥이 도구까지 이어지는지)이 버전마다 다르다.
- B 직접(추천): MCP는 `initialize`·`tools/list`·`tools/call`·`ping`만 쓰면 된다. 컨트롤러 하나가 JSON 하나를 받아 JSON 하나로 답한다(stateless). 앱이 두 벌(a·b)로 번갈아 돌아도 세션을 나눌 일이 없고, Spring Security가 정한 회원이 같은 요청 스레드에서 그대로 쓰인다. 실제 MCP 클라이언트(공식 SDK, Inspector)로 맞물리는지 확인한다.
- 지원 프로토콜 판: `2025-06-18`(기본), `2025-03-26`, `2025-11-25`.

### D-2. 어떻게 로그인하나 — **가안: 개인 열쇠(Bearer)**
- MCP 표준의 원격 로그인은 OAuth 2.1이다. 만들 것이 많아(인가 서버, 동적 등록) 추후 확장으로 둔다.
- 개인 열쇠: `gk_` + 무작위 32바이트(base64url). 저장은 SHA-256 해시와 앞 8글자만. 범위 `read`·`draft`, 기한 30/90/365일, 회원당 5개.
- 열쇠는 MCP 주소 전용 보안 사슬에서만 읽는다: 세션을 만들지 않고, CSRF 대신 Origin을 본다(브라우저가 보낸 다른 사이트 요청은 403).

### D-3. RAG를 어떻게 — **가안: 서버는 "찾기"만, 답은 사용자의 AI가**
- 후보 글: 검색어 단어가 하나라도 든 읽을 수 있는 글 최근 50개.
- 단락: 마크다운을 빈 줄로 나눈 덩어리(코드 블록은 한 덩어리, 이미지 줄은 뺀다, 600자를 넘으면 단어가 맞은 곳 둘레로 자른다). 제목 줄(`#`)만 있는 덩어리는 다음 단락 앞에 붙인다(2026-10-20 구현 중 공식 SDK로 붙어 보니 제목만 단락으로 나와 인용할 내용이 없었다).
- 점수: 단어마다 그 단락에 나온 횟수(최대 3) × 그 단어가 드문 정도(후보 글 중 몇 개에 나오나의 역수 로그) + 제목에 단어가 있으면 덤. 글마다 2개까지, 전체 8개까지.
- 서버에 임베딩이 켜져 있으면(Ollama) 뜻 검색을 더할 수 있게 틀만 나눠 둔다(이번에는 단어 점수만).

### D-4. AI가 할 수 있는 쓰기 — **가안: 임시 저장만**
- 발행·삭제·댓글은 사람이 한다. AI가 쓴 초안은 임시 저장 목록에 "AI 비서" 표시 없이 그대로 들어가고, 사람이 읽고 고쳐 올린다.

### D-5. 요청 수 제한 — **가안: 열쇠마다 1분 60번, Redis**
- 잃어도 되는 짧은 값이라 Redis(헌법 1.1.0). Redis가 안 되면 셀 수 없으니 MCP만 503으로 막는다(2026-10-20 CodeRabbit 보안 검토: 열어 두면 열쇠를 가진 쪽이 그동안 수 제한 없이 검색할 수 있다. MCP는 곁 기능이라 잠깐 멈춰도 사이트는 그대로).
