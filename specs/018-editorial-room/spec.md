# Spec: 편집실 (관리자 화면, 018, v0.13.0)

> 로드맵 [`다음-기능.md`](../../docs/2-요구사항/다음-기능.md) "나중 후보: 관리자 화면", 상세/05 CF-23-1("이번 범위에서는 관리자 화면을 만들지 않는다. 신고 내용은 데이터베이스에서 직접 확인한다")을 넘어선다. 2026-10-19 사용자 "블로그에 필요한 것 전부, 다른 사람들이랑 색다르게" → 추천대로 정한 가안.
> 글결다운 모양: 관리자 화면 이름은 **편집실**. 신고가 들어온 원고는 편집실 책상에 쌓이고, 관리자는 **내림**(비공개로 돌리고 잠금) 또는 **반려**(신고 닫기)를 붉은 도장으로 찍는다.

## 사용자 이야기

### US1 신고 검토와 내림 (P1)
1. 관리자(`users.role = admin`)만 내 메뉴에서 **편집실**(`/editorial`)로 들어온다. 관리자가 아니면 메뉴가 없고 주소로 와도 403 안내.
2. **검토 대기** 탭에 신고가 들어온 블로그 글이 글마다 한 줄로 쌓인다: 제목, 블로그, 신고 수, 사유별 수(스팸·욕설·음란·기타), 첫·마지막 신고 시각. 신고가 많은 글이 위, 같으면 오래 기다린 글이 위.
3. 한 줄을 펼치면 신고마다 사유와 기타 설명(신고한 사람은 보이지 않음)과 글 미리보기가 보인다.
4. **내림**: 사유(1~200자)를 적으면 그 글을 비공개로 돌리고 **잠근다**. 글 주인은 잠긴 글을 다시 공개로 바꿀 수 없다(고치기는 된다). 주인의 우편함에 "편집실" 소식이 사유와 함께 간다. 그 글의 대기 신고는 모두 "내림"으로 닫힌다.
5. **반려**: 그 글의 대기 신고를 모두 "반려"로 닫는다. 글은 그대로다.
6. **처리 기록** 탭: 내림·반려한 글을 최근 순으로. 내린 글은 **잠금 풀기**로 주인이 다시 공개할 수 있게 한다(자동으로 공개하지는 않는다).

**받아들이는 기준**
- S1-1 관리자가 아니면 편집실 API 모두 403, 로그인하지 않았으면 401.
- S1-2 이미 닫힌 신고만 있는 글을 다시 처리하면 409 `REPORT_ALREADY_RESOLVED`. 처리 뒤 새 신고가 오면 다시 대기에 올라온다.
- S1-3 잠긴 글을 주인이 공개로 바꾸려 하면 400 `POST_LOCKED_BY_EDITOR`(비공개로 두고 고치는 것은 된다). 임시 저장·예약 발행은 새 글만 만들므로 잠금과 상관없다.
- S1-4 지워진 글의 신고는 대기에 나오지 않는다(글을 지우면 신고도 지워진다, 지금과 같음).
- S1-5 내림 소식을 만들다 실패해도 내림은 그대로 된다.

### US2 글마당 신고 (P2)
1. 글마당 글에도 **신고** 단추가 있다(로그인, 자기 글은 안 됨, 같은 사람 한 번). 사유는 블로그 글과 같다.
2. 편집실 검토 대기에 **글마당** 탭이 따로 있고, 처리는 **지우기**(글과 댓글을 지운다, 쓴 사람 우편함에 사유와 함께 소식) 또는 **반려**.

**받아들이는 기준**
- S2-1 자기 글 신고 403, 두 번 신고 409(블로그 글과 같은 코드), 없는 글 404.
- S2-2 지운 글마당 글의 신고는 함께 지워지고, 처리 기록에는 그때의 제목만 남는다.

### US3 운영 현황 (P2)
1. 편집실 첫 화면 위에 숫자 카드: 회원(탈퇴 제외), 오늘 가입, 블로그 글(공개), 오늘 올라온 공개 글, 글마당 글, 검토 대기 신고.
2. 숫자는 원고지 칸 숫자로 보인다(블로그 관리 대시보드와 같은 모양).

**받아들이는 기준**
- S3-1 "오늘"은 한국 날짜(서비스 날짜 설정)로 센다.
- S3-2 숫자는 요청마다 센다(관리자만 보므로 캐시하지 않는다).

## 범위 밖
- 회원 정지·강제 탈퇴, 댓글 신고, 자동 숨김(신고 N건이면 자동 내림), 신고한 사람에게 결과 알리기.
