## 구현 방식 (가안)

- Spring Security OAuth2 Client(`oauth2Login`). 회사 목록은 우리 설정(`social.providers.*`)에서 열쇠가 있는 것만 만든다 (스프링 기본 설정은 열쇠가 비면 서버가 안 켜져서 쓰지 않는다).
- GitHub·Google은 Spring에 들어 있는 주소를, Kakao·Naver는 주소를 직접 적는다. Google은 `openid` 없이 `profile email`만 받아 네 회사가 같은 길(회원 정보 주소)을 탄다.
- 회사가 돌려준 값은 `SocialProfile`(회사, 회사 쪽 번호, 이메일, 인증 여부, 이름)로 맞춘다. GitHub 이메일은 `/user/emails`를 한 번 더 읽는다.
- 로그인을 마치면 성공 처리기가 세션의 로그인 정보를 우리 회원(`MemberPrincipal`)으로 바꾼다. 처음 사용자는 로그인시키지 않고 세션에 "가입 대기"만 남긴 채 `/signup/social`로 보낸다.
- 연결하기는 먼저 `POST /api/v1/account/social/{회사}/link`(CSRF 보호)로 세션에 "연결하려는 회원"을 적은 뒤 회사 화면으로 간다.
- 표: `user_social_account`(회원, 회사, 회사 쪽 번호, 연결 시각). `(회사, 회사 쪽 번호)`와 `(회원, 회사)`가 각각 하나뿐. `users.password`는 비어 있을 수 있다. Flyway V10. ERD는 Crowfoot 666과 `ERD-변경-요청.md` E-8.
- 콜백 주소 `{주소}/login/oauth2/code/{회사}`. 로컬은 Vite 프록시가 `/oauth2`, `/login/oauth2`를 서버로 넘기고(Host를 그대로 두어 주소가 `localhost:5173`), 배포는 화면 컨테이너 Nginx가 넘긴다 (`forward-headers-strategy`로 원래 주소를 안다).
