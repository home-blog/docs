# API 버전과 릴리스 (쉬운 설명)

> 2026-10-12 정리 (사용자 결정: 릴리스는 항상 문서로 남기고, API에도 반영한다). 코드에서는 v0.4.0부터 적용된다.
> 어떻게 만들었는지는 [`specs/009-api-version-release`](../../specs/009-api-version-release/spec.md)와 코드 저장소 `CHANGELOG.md`에 있다.

## 1. 번호가 두 개 있다

| | 릴리스 버전 | API 버전 |
|---|---|---|
| 생김새 | `0.4.0` (태그 `v0.4.0`) | 주소 안의 `v1` (`/api/v1/posts`) |
| 무엇의 번호 | 서비스 전체(화면 + 서버)를 **한 번 배포한 묶음** | 서버와 화면(또는 다른 앱) 사이의 **약속**: "이 주소로 물으면 이런 모양으로 답한다" |
| 언제 올리나 | **배포할 때마다**. 디자인만 바꿔도 올린다 | 그 약속이 **깨질 때만** |
| 어디서 보나 | 화면 맨 아래 바닥글, `CHANGELOG.md`, GitHub 릴리스 | 바닥글, API 문서(개발 서버 `/swagger-ui.html`) 머리 |

비유하면 **릴리스 버전은 잡지의 호수**(매달 1호, 2호…), **API 버전은 잡지의 판형**이다. 매달 새 호가 나와도 판형은 그대로라서 책꽂이(쓰는 쪽)를 바꿀 필요가 없다. 판형이 바뀔 때만 책꽂이를 새로 맞춘다.

## 2. 무엇이 "약속이 깨진 것"인가

API 응답은 칸(이름: 값)들의 묶음이다. 예: `{ "title": "제목", "preview": "앞부분" }`

| 바꾼 것 | 예전 화면은? | API 버전 |
|---|---|---|
| 칸을 **더함** (`thumbnail` 추가) | 모르는 칸은 그냥 무시해서 그대로 동작 | **v1 그대로** |
| 받는 값을 더함 (선택 칸, 새 주소) | 안 쓰면 그만 | **v1 그대로** |
| 칸을 **뺌**, 칸 **이름**을 바꿈 (`preview` → `summary`) | 찾던 칸이 없어 빈칸이 보임 | **v2** |
| 칸의 **뜻·모양**을 바꿈 (날짜를 글자 → 숫자로) | 엉뚱하게 보이거나 오류 | **v2** |
| 꼭 보내야 하는 값을 새로 요구 | 예전 요청이 거절됨 | **v2** |

## 3. v2를 열면 어떻게 되나

1. 바뀌는 주소만 v2 처리기를 새로 만든다. 나머지 주소는 v1·v2 둘 다에 똑같이 답한다.
2. **예전 v1은 한동안 같이 둔다.** 아직 예전 화면(브라우저에 남은 옛 화면, 나중에 만들 앱)이 v1을 부를 수 있어서다.
3. v1을 없앨 날을 정하고, 응답에 "곧 없어진다"는 표시(Deprecation)를 붙여 알린 뒤 지운다.
4. 이 모든 것을 그 릴리스의 `CHANGELOG.md` `API` 줄에 적는다.

글결은 화면과 서버를 같은 릴리스로 함께 배포하므로 v2가 필요한 일은 드물다. 그래도 나중에 휴대폰 앱이나 다른 서비스가 붙으면 이 규칙이 그쪽을 지켜 준다.

## 4. 릴리스 주기 (2026-10-12)

**로컬에서 어느 정도 해 두고 → 버전을 올려 → 배포**한다. 아주 작은 변경마다 내지 않고, 쓸 만한 묶음(기능 한두 개, 모인 버그 수정)이 되면 화면을 확인하고 낸다.

| 이번 묶음에 | 번호 | 예 |
|---|---|---|
| 기능이 있다 | 가운데 숫자를 올린다 | 0.4.x → 0.5.0 |
| 버그 수정만 있다 | 끝 숫자를 올린다 | 0.4.0 → 0.4.1 |
| 서비스가 멈추는 급한 버그 | 그것만 따로 바로 낸다 | 0.4.1 |

## 5. 릴리스마다 하는 일 (문서로 남기기)

1. `CHANGELOG.md`에 그 버전의 절을 쓴다: **화면 / API / 운영**으로 나눠서. API 줄에는 "v1 그대로, `thumbnail` 칸 추가"처럼 버전과 바뀐 칸을 함께 적는다.
2. 서버(`backend/pom.xml`)와 화면(`frontend/package.json`)의 버전 번호를 같은 번호로 맞춘다.
3. 화면을 확인하고 "배포해줘"가 나오면 Actions `배포`를 손으로 돌리며 번호를 넣는다. 배포 작업이 번호·버전·CHANGELOG가 맞는지 먼저 확인하고(다르면 멈춘다), 배포에 성공하면 GitHub 릴리스(`v0.4.1`)를 CHANGELOG의 그 절로 만든다.

## 6. 예외: 이미지 파일 주소

글에 넣은 사진 주소(`/api/images/{파일}`)는 **글 본문에 그대로 저장**된다. 주소에 버전을 붙이면 v2가 나올 때 옛 글의 사진이 깨지므로, 이미지 파일 주소만 버전 없이 고정한다. 사진을 올리는 요청은 `/api/v1/images`다.
