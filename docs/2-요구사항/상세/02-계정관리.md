# 02. 계정관리 (마이페이지)

> 로그인한 회원이 자기 계정을 관리하는 규칙입니다. (내 정보 수정, 비밀번호 변경, 회원 탈퇴)
> 관련 파일: [01-인증-인가](01-인증-인가.md)
> 읽는 법과 ID 규칙은 [00-목차.md](00-목차.md)를 봅니다.

## 요구사항

### 마이페이지 (CF-15) — 상태: 화면 없음

| ID | 요구사항 | 상세 |
|---|---|---|
| CF-15-1 | 구성 | **내 정보**, **비밀번호 변경**, **회원 탈퇴**, **내 블로그 바로가기**로 구성한다. |
| CF-15-2 | 접근 | 로그인한 본인만 볼 수 있다. 로그인하지 않았으면 CF-16-1과 같이 로그인 창을 띄운다. 다른 회원의 마이페이지는 볼 수 없다. |
| CF-15-3 | 내 정보 보기 | 이메일, 닉네임, 소개, 가입일을 보여 준다. |
| CF-15-4 | 이메일 | 이메일은 로그인 아이디 역할이라 **바꿀 수 없다.** |
| CF-15-5 | **내 정보 수정** | **닉네임**과 **소개**를 바꿀 수 있다. 닉네임은 CF-01-3 규칙을 따르고(내 닉네임 그대로는 중복이 아니다), 소개는 0~100자이다. |
| CF-15-6 | 저장 | 바뀐 것이 없으면 저장 버튼이 눌리지 않는다. 저장하면 "저장했습니다"를 보여 주고, 오류는 칸 아래에 보여 준다. |
| CF-15-7 | 이탈 확인 | 수정하던 중 다른 화면으로 가려 하면 "저장하지 않은 내용이 있습니다. 나갈까요?"를 묻는다. |
| CF-15-8 | 프로필 사진 | 이번 범위에서는 만들지 않는다. |
| CF-15-9 | 바로가기 | "내 블로그"를 누르면 내 블로그 화면으로 이동한다. |

### 비밀번호 변경 (CF-15) — 상태: 화면 없음

| ID | 요구사항 | 상세 |
|---|---|---|
| CF-15-10 | 입력 | 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 입력한다. 모두 필수이다. |
| CF-15-11 | 현재 비밀번호 확인 | 현재 비밀번호가 맞아야 진행한다. 틀리면 "현재 비밀번호가 올바르지 않습니다"를 보여 준다. |
| CF-15-12 | 새 비밀번호 규칙 | CF-01-4와 같다. 그리고 **현재 비밀번호와 같으면 안 된다.** |
| CF-15-13 | 확인 일치 | 새 비밀번호와 확인 입력이 같아야 한다. |
| CF-15-14 | 연속 오입력 | 현재 비밀번호를 틀린 횟수는 로그인 실패 횟수와 **합산**한다. 연속 5회가 되면 CF-02-6처럼 10분간 잠근다. |
| CF-15-15 | 변경 후 | "비밀번호를 변경했습니다"를 보여 준다. 지금 사용 중인 기기의 로그인은 유지하고, **다른 모든 기기의 로그인은 끊는다.** |
| CF-15-16 | 변경 알림 메일 | 비밀번호가 바뀌면 가입 이메일로 알려 준다. (선택. 본인이 바꾸지 않았을 때 알아채기 위해) |

### 회원 탈퇴 (CF-15) — 상태: 화면 없음

| ID | 요구사항 | 상세 |
|---|---|---|
| CF-15-17 | 본인 확인 | 탈퇴하려면 **비밀번호를 다시 입력**해야 한다. 틀리면 CF-15-11 문구를 보여 주고, 실패 횟수는 CF-15-14에 합산한다. |
| CF-15-18 | 안내 | 되돌릴 수 없다는 것, **삭제되는 것**(내 블로그, 글, 분류, 내가 쓴 댓글 중 내 블로그 안의 것, 좋아요)과 **남는 것**(다른 사람 글에 단 댓글, 작성자는 "탈퇴한 사용자"로 표시)을 보여 준다. |
| CF-15-19 | 재확인 | 안내를 읽었다는 체크를 해야 `탈퇴하기`가 눌린다. 누르면 "정말 탈퇴하시겠습니까? 이 작업은 되돌릴 수 없습니다"를 한 번 더 묻는다. |
| CF-15-20 | 탈퇴 후 | 바로 로그아웃하고 첫 화면에서 "탈퇴가 완료되었습니다"를 보여 준다. |
| CF-15-21 | 재가입 | 같은 이메일과 닉네임으로 **다시 가입할 수 있다.** 새 계정이며 이전 데이터는 복구할 수 없다. |
| CF-15-22 | 개인정보 지우기 | 탈퇴하면 그 회원의 이메일, 비밀번호, 닉네임, 소개를 **누구였는지 알아볼 수 없는 값으로 바꾸거나 지운다.** 회원 기록은 남은 댓글의 작성자 표시를 위해 남기되, 누구였는지는 알 수 없게 한다. (2026-10-08 추가) |

## 구현 방식

> 상태 표기: **확정**(정했음) / **가안**(바뀔 수 있음) / **미정**(아직 정하지 않음). 자세한 기술 설명과 그림은 [기술스택-아키텍처.md](../../3-설계/기술스택-아키텍처.md)에 있습니다.

> 2026-10-08: US1(마이페이지), US2(비밀번호 변경), US3(회원 탈퇴)를 코드로 만들었다. US4(비밀번호 변경 알림 메일)는 이번에 넣지 않는다. 자세한 것은 [`specs/002` plan](../../../specs/002-account-management/plan.md)과 [계약](../../../specs/002-account-management/contracts/account-api.md).

#### 쉬운 설명

- 마이페이지의 모든 요청은 **주소에 회원 번호가 없다.** 서버는 번호표(세션)로 "로그인한 나"를 알아보고, 나의 정보만 돌려주거나 고친다. 그래서 남의 마이페이지를 열 방법이 없다.
- 비밀번호를 확인하는 곳은 **한 곳**이다. 로그인, 비밀번호 변경, 탈퇴가 같은 확인 방법을 쓰므로, 어디서 틀려도 같은 칸에 횟수가 쌓이고 5번째에 10분 잠긴다.
- 비밀번호를 바꾸면 서버의 명부(세션 표)에서 **나의 줄 중 지금 기기만 남기고** 모두 지운다. 다른 기기는 다음 요청에서 로그아웃된다.

| 항목 | 내용 | 상태 |
|---|---|---|
| 쓰는 DB 표 | 회원 표 (닉네임, 소개, 해시된 비밀번호, 로그인 실패 횟수 `failed_login_count`와 잠금 해제 시각 `locked_until`). 실패 횟수 두 칸은 팀 ERD에 없는 내 확장(E-1)이고 이미 만들어져 있다 | 가안 |
| 내 블로그 바로가기 | 회원 기능이 블로그 기능을 직접 부르지 않도록, 회원 쪽이 "이 회원의 블로그 번호는?"이라는 질문 틀을 정하고 블로그 쪽이 답을 채운다 (CF-15-2) | 가안 (만듦) |
| 소개 글자 수 | 0~100자. 이모지 하나도 한 글자로 센다. 숫자는 설정 한곳(`기본값` 표와 같음)에서 읽고, DB 칸(100자)보다 크게 정하면 서버가 켜지지 않는다 (CF-15-5) | 가안 (만듦) |
| 현재 비밀번호 확인 | 로그인과 **같은 확인 방법**을 그대로 쓴다. 틀리면 로그인 실패와 같은 칸에 +1, 5번째에 10분 잠금, 맞으면 0으로 되돌린다. 틀렸을 때의 응답은 "로그인이 필요함"이 아니라 "현재 비밀번호가 올바르지 않음"이다 (CF-15-11, CF-15-14, CF-15-17, `specs/002` D-3, D-4) | 가안 (만듦) |
| 세션을 쓰는 지점 | 비밀번호를 바꾸면 새 비밀번호를 저장한 **뒤에** 그 회원의 **다른 세션을 모두 삭제**한다. 탈퇴하면 그 회원의 세션을 모두 삭제한다 ([인증과 세션](01-인증-인가.md)) | 확정 (방식) / 만듦 |
| 탈퇴 시 데이터 | 블로그·글·분류·내 블로그 안의 댓글은 삭제, **다른 사람 글에 단 댓글은 그대로 두고 "탈퇴한 사용자"로 표시**. 회원 줄은 지우지 않고 `deleted_at`(탈퇴 표시)을 넣으며, 개인정보는 알아볼 수 없게 바꾼다: 이메일 → `deleted-{회원번호}@deleted.invalid`, 비밀번호 → 해시를 지우고 어떤 비밀번호와도 맞지 않는 값(`!deleted`), 닉네임 → `탈퇴한사용자{회원번호}`, 소개 → 비움(NULL). 화면은 `deleted_at`을 보고 "탈퇴한 사용자"로 보여 준다 (2026-10-08, `specs/002` D-1, D-2). 지금 지우는 것은 블로그와 분류이고, 글·댓글·좋아요는 그 기능(003, 005)이 생길 때 같은 방식으로 더한다 | 확정 (만듦) |
| 탈퇴 정리 방법 | 회원 기능이 "탈퇴했다"는 알림(이벤트)을 내면, 블로그·글·댓글 기능이 각자 듣고 **자기 데이터를 스스로** 지운다. 모두 한 묶음이라 하나라도 실패하면 탈퇴 전체가 취소된다 (CF-15-18). 회원 줄을 먼저 바꾸고 알림을 낸다 (`MemberWithdrawnEvent` → 블로그 기능의 `BlogClosingEvent`) | 확정 (만듦) |
| 중복 검사 | 이메일·닉네임은 대소문자 구분 없이, **탈퇴하지 않은 회원에게만** DB 제약으로 중복을 막는다. 그래서 탈퇴한 사람은 같은 이메일·닉네임으로 다시 가입할 수 있다. 탈퇴 때 이메일·닉네임을 바꾸므로(CF-15-22) 평범한 중복 불가만으로도 재가입이 된다 (CF-15-21, `specs/001` D-4) | 가안 |
| 비밀번호 변경 알림 메일 | 이번에는 만들지 않는다. 추후 확장 후보 (CF-15-16, `specs/002` D-6) | 결정됨 (만들지 않음) |
