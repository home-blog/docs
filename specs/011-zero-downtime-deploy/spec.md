# Feature Specification: 무중단 배포 (v0.5.2)

**Feature**: `011-zero-downtime-deploy` · **Created**: 2026-10-14 · **Status**: 구현 끝, 로컬 확인 끝, 사용자 확인 대기 (코드 브랜치 `feature/zero-downtime`)

**요청 (2026-10-14 사용자, 강사님 안내)**: "Nginx 파일에 애플리케이션 두 개를 띄워서 트래픽이 어떤지 확인해 보고 무중단 배포를 해 봐라." 로드맵 v0.5.2 무중단 배포를 이 방향으로 만든다. 빈 곳은 [research.md](research.md)의 D-항목(가안)으로 채운다.

쉬운 설명: 지금은 배포할 때 옛 서버를 끄고 새 서버를 켜서, 새 서버가 켜지는 수십 초 동안 사이트가 멈춘다. 앞으로는 같은 앱을 **두 벌(a, b)** 늘 같이 띄워 두고, 학원 Nginx가 손님을 두 벌에 번갈아 보낸다. 배포할 때는 **한 벌씩** 바꾼다. 한 벌을 바꾸는 동안 다른 벌이 손님을 받으니 사이트가 멈추지 않는다. 쉬운 설명 전체는 [`docs/4-가이드/08-무중단-배포.md`](../../docs/4-가이드/08-무중단-배포.md).

## 사용자 이야기

### US1 배포하는 동안에도 사이트를 쓸 수 있다 (P1)
1. 방문자는 배포하는 동안에도 글 목록·글 읽기·첫 화면이 오류 없이 열린다.
2. 로그인한 회원은 배포 뒤에도 로그인이 유지된다.
3. 새 버전이 고장 나 있으면(켜지지 않거나 확인에 실패) 그 버전은 손님에게 가지 않고, 사이트는 옛 버전으로 계속 돈다. 배포는 실패로 끝나고 운영자는 무엇이 실패했는지 본다.

### US2 운영자가 트래픽이 어떻게 나뉘는지 본다 (P1)
1. 응답마다 어느 벌이 받았는지 볼 수 있다 (학원 Nginx가 붙이는 `X-Upstream`, 앱이 붙이는 `X-Instance`).
2. 학원 Nginx 접속 로그에서 벌마다 요청 수와 다른 벌로 다시 보낸 요청을 셀 수 있다.

### US3 운영자가 옛 버전으로 되돌린다 (P2)
1. 서버에 남은 바로 전 이미지로 한 줄 명령으로 되돌릴 수 있고, 되돌리는 동안에도 사이트가 멈추지 않는다.

## 기준 (Success Criteria)
- SC-001: 1초에 70번쯤 요청을 보내며 배포해도 GET 실패 0. (로컬에서 학원 Nginx와 같은 설정으로 잰다)
- SC-002: 고장 난 버전을 배포해도 실패 0, 두 벌 모두 옛 버전으로 남는다.
- SC-003: 두 벌 이전 구성(v0.5.1)에서 이 버전으로 처음 넘어갈 때도 실패 0.
- SC-004: 트래픽이 두 벌에 거의 반씩 나뉜다.

## 범위 밖
- 서버 여러 대, DB 이중화 (학원 서버 한 대, DB 하나)
- 카나리(일부 손님만 새 버전), 모니터링 그래프(Prometheus·Grafana): 추후 확장 후보
