# Research: 발견 (015)

`가안`은 사용자가 정하기 전 추천대로 정한 것(2026-10-19 사용자 "알아서"). 바꾸고 싶으면 그 줄만 고친다.

| ID | 정할 것 | 고른 것 | 다른 선택지 | 이유 |
|---|---|---|---|---|
| D-1 | 인기 검색어를 어디에 세나 | **Redis 정렬 집합**을 10분 칸마다 하나(`search:count:{칸}`), 1시간 6칸을 합쳐 순위. 칸은 70분 뒤 저절로 지움 `가안` | DB 표에 검색 기록 | 잃어도 되는 짧은 값(헌법 1.1.0). 두 벌이 같은 Redis를 본다 |
| D-2 | 변화(▲▼) | 지금 1시간(6칸)과 10분 전 1시간(한 칸 앞 6칸)을 둘 다 계산해 견준다. 보관하지 않고 부를 때마다 센다(칸 12개를 읽을 뿐). 같은 수면 검색어 가나다순 `확정`(2026-10-19 구현) | 1분마다 순위를 저장하는 정리 작업 | 정리 작업·잠금이 필요 없다 |
| D-3 | 중복 | 같은 사람(회원 번호, 없으면 방문자 쿠키)·같은 말은 10분에 한 번(`search:seen:*`, SET NX) `가안` | 1시간 | 새로 고침 장난을 막되, 정말 다시 찾는 사람은 센다 |
| D-4 | 무엇을 세나 | 결과가 1개 이상인 검색만, 금지어는 빼고 `가안` | 모든 검색 | 오타·장난이 순위에 오르지 않게 |
| D-5 | 오늘의 이슈 기준 | 통계 표(`post_daily_stat`)의 오늘 + 어제 조회 수 합(한국 날짜), 블로그당 1개, 고른 글 번호만 5분 보관(날짜가 바뀌면 다시)·카드는 요청마다 다시 읽음 `확정`(2026-10-19 구현) | 최근 24시간 정확히(시간별 표) | 하루 단위 통계가 이미 있다. 자정 직후에도 비지 않는다 |
| D-6 | 문장 수집 표 | 새 표 `sentence_clip`(V17), 원문 글이 지워지면 글 번호만 비우고(SET NULL) 제목·블로그 이름은 모을 때 적어 둔다 | 글이 지워지면 문장도 지움 | N-15 "문장은 남기되 볼 수 없는 글로" |
| D-7 | 본문에 있는 문장인지 | 본문과 문장에서 마크다운 기호·공백을 빼고 견준다 `가안` | 검사 안 함 | 남의 글에 없는 말을 그 글의 문장처럼 남기지 못하게. 화면에서 고른 글자는 마크다운이 풀린 모양이라 그대로 견주면 맞지 않는다 |
| D-8 | 필사 노트 모양 | 원고지 칸(한 줄 20칸)에 한 글자씩, 칸 수는 화면 폭에 맞춰 | 인용 상자 | 글결의 원고지 콘셉트로 다른 블로그와 다르게 |
| D-9 | 모듈 | 인기 검색어는 글 모듈이 검색 뒤 `PostSearchedEvent`를 내고 통계 모듈이 센다(방문자 구분 `VisitorKeyResolver`가 통계 모듈 안에 있음), 오늘의 이슈는 글 모듈(이번 주 인기 글과 같은 `PostFeedRepository` SQL 방식), 문장 수집은 커뮤니티 모듈(좋아요·신고 옆, 글은 `PostLookup.findVisibleText`로 묻는다). 2026-10-19 구현하며 바로잡음 | 새 모듈 | 모듈 방향(`user ← blog ← post ← comment/community`, `stats` 읽기만)을 지킨다 |
