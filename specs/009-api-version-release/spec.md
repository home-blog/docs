# Feature Specification: API 주소 버전과 릴리스 기록 (v0.4.0)

**Feature**: `009-api-version-release` · **Created**: 2026-10-12 · **Status**: 구현 끝, PR 대기

**요청 (2026-10-12 사용자)**: "API나 문서에 릴리스 잘 반영하고 있지? /api/v1 → /api/v2 이런 식으로 바꾸면 좋아" → "릴리스는 항상 잘 문서화해 놔야 해. API도 반영하면 좋지" → 추천대로(주소 버전은 깨지는 변경 때만, 릴리스는 항상 기록).

쉬운 설명: [API 버전과 릴리스](../../docs/4-가이드/06-API-버전과-릴리스.md)

## 사용자 이야기

### US1 API 주소에 버전 (P1)
1. 모든 서버 API 주소는 `/api/v1/…` 이다. 지금 버전은 v1 하나다.
2. 버전이 없는 예전 주소(`/api/posts`)나 모르는 버전(`/api/v9/posts`)은 로그인 여부와 상관없이 "※ 지원하지 않는 API 버전입니다"(400)로 답한다.
3. 글 본문에 저장되는 이미지 파일 주소(`/api/images/{파일}`)는 버전 없이 그대로다. 로봇용 주소(`/og`, `/rss.xml`, `/sitemap.xml`, `/robots.txt`)도 그대로다.
4. API 버전은 릴리스와 따로 간다. 칸을 더하는 변경은 v1 그대로, 칸을 빼거나 이름·뜻을 바꾸는 변경일 때만 v2를 열고 v1은 한동안 같이 둔다.

### US2 릴리스는 항상 기록 (P1)
1. 릴리스마다 바뀐 것을 **화면 / API / 운영**으로 나눠 기록한다(코드 저장소 `CHANGELOG.md`). API 줄에는 버전(그대로인지, 새로 열었는지)과 바뀐 칸을 적는다.
2. 서버와 화면의 버전 번호를 릴리스 번호와 같게 맞춘다.
3. 배포는 릴리스 태그·버전 번호·기록이 맞을 때만 한다(안 맞으면 멈추고 알린다).

### US3 지금 버전이 보인다 (P2)
1. 화면 맨 아래에 릴리스 번호, API 버전, 바뀐 것 기록으로 가는 링크가 보인다.
2. 개발 서버에서 자동 API 문서를 볼 수 있고, 머리에 API 버전과 릴리스 번호가 함께 보인다. 배포 서버에서는 문서를 열지 않는다(가안).

## 성공 기준
- SC-1 화면의 모든 요청이 `/api/v1/…`로 가고 가입·로그인·글쓰기·로그아웃이 그대로 된다.
- SC-2 `/api/posts`, `/api/v9/posts`는 400 `API_VERSION_UNSUPPORTED`.
- SC-3 `CHANGELOG.md`에 v0.1.0, v0.3.0, v0.4.0 절이 있고, 바닥글에 "릴리스 v0.4.0 · API v1"이 보인다.
