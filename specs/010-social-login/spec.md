# Feature Specification: 소셜 로그인 (v0.5.0)

**Feature**: `010-social-login` · **Created**: 2026-10-12 · **Status**: 구현 끝, 사용자 확인 대기 (코드 브랜치 `feature/v0.5-social-login`)

**요청 (2026-10-12 사용자)**: 로드맵 [N-07](../../docs/2-요구사항/다음-기능.md) "GitHub·Kakao·Naver·Google 로그인"을 "추천대로" 넣는다. 이 문서는 그 가안을 명세로 옮기고, 빈 곳은 [research.md](research.md)의 D-항목(가안)으로 채운다.

쉬운 설명: 이메일과 비밀번호를 새로 만들지 않고, 이미 쓰는 GitHub·카카오·네이버·구글 계정으로 "이 사람이 맞다"는 확인을 받아 들어온다. 들어온 뒤에는 이메일 로그인과 똑같이 서버 세션으로 로그인 상태를 유지한다. 회사가 준 토큰(열쇠)은 보관하지 않는다.

## 사용자 이야기

### US1 소셜 계정으로 로그인 (P1)
1. 로그인 창과 회원가입 창에 회사별 로그인 버튼이 있다. 서버에 열쇠(앱 등록 값)가 들어 있는 회사의 버튼만 보인다 (D-9).
2. 이미 연결된 소셜 계정이면 회사 화면에서 허락한 뒤 바로 로그인되어 첫 화면으로 돌아온다.
3. 비밀번호를 여러 번 틀려 잠긴 회원도 소셜 로그인은 된다 (D-5).
4. 회사 화면에서 취소하거나 오류가 나면 로그인 창으로 돌아와 "※ 소셜 로그인을 마치지 못했습니다. 다시 시도해 주세요"를 본다.

### US2 처음 들어오는 사람은 닉네임만 정하고 가입 (P1)
1. 연결된 회원이 없으면 "소셜 가입" 화면으로 간다. 회사가 알려 준 이름을 닉네임 칸에 미리 넣어 두되, 규칙(2~10자, 한글·영문·숫자)에 맞지 않거나 이미 있으면 비워 둔다.
2. 회사가 **인증된 이메일**을 알려 주면(D-2) 그 이메일을 그대로 쓰고, 닉네임만 입력하면 가입이 끝난다.
3. 이메일을 주지 않거나 인증되지 않은 이메일이면, 기존 이메일 인증번호 절차(001)로 이메일을 확인받은 뒤 가입한다.
4. 가입이 끝나면 블로그와 미분류 분류가 만들어지고(001과 같다), **바로 로그인**된다 (D-3).
5. 회사 화면을 다녀온 뒤 10분 안에 가입을 마쳐야 한다. 지나면 "※ 시간이 지났습니다. 소셜 로그인을 다시 해 주세요" (D-8).

### US3 같은 이메일의 기존 계정과 연결 (P1)
1. 회사가 **인증한** 이메일과 같은 이메일로 가입한 회원이 있으면, 자동으로 그 회원에 연결하고 로그인한다 (D-1).
2. 인증되지 않은 이메일이 기존 회원과 같으면 자동으로 연결하지 않는다. 가입 화면에서 "이미 가입된 이메일입니다. 그 계정으로 로그인한 뒤 마이페이지에서 연결해 주세요"를 본다.

### US4 마이페이지 "연결된 계정" (P2)
1. 회사마다 연결됨/연결 안 됨이 보이고, 연결하기·연결 해제를 할 수 있다.
2. 연결하기를 누르면 회사 화면을 다녀와 마이페이지로 돌아오고 "연결했습니다"를 본다. 그 소셜 계정이 이미 다른 회원과 연결돼 있으면 "※ 이미 다른 회원과 연결된 계정입니다".
3. 로그인할 방법이 하나만 남으면(비밀번호도 없고 소셜도 하나) 해제할 수 없다: "※ 로그인할 방법이 하나는 있어야 합니다. 비밀번호를 먼저 만들어 주세요" (D-6).
4. 소셜로만 가입한 회원은 비밀번호가 없다. 마이페이지의 비밀번호 칸은 "비밀번호 만들기"가 되고, 현재 비밀번호 없이 새 비밀번호만 입력한다 (D-4). 만든 뒤에는 이메일 로그인도 된다.

### US5 탈퇴 (P2)
1. 탈퇴하면 연결 정보도 지운다. 같은 소셜 계정으로 다시 들어오면 새 회원으로 가입한다.
2. 비밀번호가 없는 회원은 탈퇴할 때 비밀번호 대신 탈퇴 안내 동의만 확인한다 (D-4).

## 성공 기준
- SC-1 연결된 회원은 회사 버튼 → 허락 → 첫 화면까지 한 번에 로그인된다(세션 쿠키, `GET /api/v1/auth/me` 200).
- SC-2 인증된 이메일의 처음 사용자는 닉네임 하나만 입력해 가입·로그인된다.
- SC-3 소셜 계정 하나는 회원 하나에만, 회원 하나는 회사마다 소셜 계정 하나만 연결된다 (DB가 막는다).
- SC-4 서버에 회사 토큰·비밀번호 대신 쓰는 값이 남지 않는다. 열쇠(Client Secret)는 환경 변수로만 넣는다.
- SC-5 열쇠가 하나도 없으면 버튼이 하나도 보이지 않고 기존 로그인·가입은 그대로다.

## 범위 밖
- 회사 쪽 프로필 사진·이름을 가져와 계속 맞추기. 가입 때 닉네임 제안에만 쓴다.
- Google은 배포 사이트에 HTTPS가 붙어야 등록할 수 있다(Google 정책). 그 전에는 로컬(localhost)에서만 시험한다.
