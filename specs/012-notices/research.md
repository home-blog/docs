## 구현 방식 (가안)

- Flyway V11: `users.role VARCHAR(10) NOT NULL DEFAULT 'member'`, `CHECK (role IN ('member','admin'))`. 새 표 `notice`. ERD는 `ERD-변경-요청.md` E-9, Crowfoot 666은 배포 DB에 V11이 생긴 뒤 DB → 문서 동기화.
- 회원 모듈의 맨 위 틀 `LoggedInMember`에 `requireAdminIdOf(authentication)`를 더한다: 로그인 안 함·탈퇴 → 401, 관리자 아님 → 403 `FORBIDDEN`. 공지 모듈은 이것만 부른다.
- 쓰기 주소는 보안 설정에서 "로그인 필요"(GET 아님), 관리자 확인은 서비스가 한다(D-2). 읽기(GET `/api/*/notices/**`)는 누구나.
- 설정 `notice.*`: 제목·본문 글자 수, 한 쪽 글 수, 릴리스 링크 틀. 글자 수는 코드 포인트로 센다(이모지 한 글자).
- 화면: `/notices`(탭 `?kind=`, 쪽 `?page=`), `/notices/:id`, 관리자만 `/notices/new`, `/notices/:id/edit`. 본문 보기는 글 읽기의 마크다운 도구를 그대로 쓴다. 꼬리표 색은 `index.css` 토큰(`--accent` 초록, `--highlight` 형광펜).
- 테스트 먼저(테스트 전략): 서버는 권한(비회원·일반 회원·관리자·관리자에서 뺀 회원·탈퇴한 관리자), 입력 경계값(제목 0·1·100·101자, 번호 모양), 정렬·탭·쪽. 화면은 탭·꼬리표·고정 표시, 관리자 버튼 보이기, 새 글 점, 입력 검사.
