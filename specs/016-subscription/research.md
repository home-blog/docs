# Research: 구독·알림 (016)

`가안`은 추천대로 정한 것(2026-10-19 사용자 "알아서, 색다르게"). 바꾸고 싶으면 그 줄만 고친다.

| ID | 정할 것 | 고른 것 | 다른 선택지 | 이유 |
|---|---|---|---|---|
| D-1 | 모듈 | 새 모듈 `subscription`(구독·우편함·편지). 블로그·글·댓글 모듈의 맨 위 타입과 이벤트만 쓴다: `allowedDependencies = comment, post, blog, user, common` `가안` | 구독은 blog, 알림은 새 모듈 | 받아 보기·소식·편지가 한 흐름이다. 아래 모듈은 이 모듈을 모른다(이벤트로만) |
| D-2 | 새 글을 어떻게 아나 | 글 모듈이 글이 **처음 공개된 순간**(바로 발행, 예약 발행, 비공개→공개로 처음 바꿈) `PostPublishedEvent(postId, blogId, ownerId, title)`를 낸다. 글 표에 `first_published_at`을 두어 두 번 내지 않는다 `가안` | 저장할 때마다 이벤트 | S2-2 "처음 공개될 때만" |
| D-3 | 언제 소식을 만드나 | `@TransactionalEventListener(AFTER_COMMIT)` + `@Async` 일꾼이 받아 보는 사람마다 소식 줄을 한 번에 넣는다(`insert … select`) `가안` | 같은 트랜잭션 | S2-3 글 저장이 소식 때문에 느려지거나 실패하지 않게 |
| D-4 | 안 읽은 수 | 화면이 1분마다 `GET /me/notifications/unread-count`(창이 보일 때만) `가안` | SSE | 두 벌 이중화·학원 Nginx에서 오래 열린 연결이 번거롭다 |
| D-5 | 보관 | 30일, 매일 새벽 4시(한국) 정리 작업, 두 벌 가운데 잠금을 잡은 한 벌만 `가안` | 영구 | 표가 끝없이 자라지 않게 |
| D-6 | 메일 | 기존 메일 보내기(`MailSender`, 서비스 Gmail)를 쓰되 글 저장 뒤 일꾼이 받는 사람마다 한 통씩. 하루 한도는 Redis 날짜 키로 센다(잃으면 그날 조금 더 보낼 수 있음) `가안` | 메일 서비스(유료) | 돈이 들지 않는다(2026-10-19 사용자) |
| D-7 | 그만 받기 링크 | `HMAC(구독 번호)`를 서버 비밀값으로 서명한 값, 로그인 없이 `POST`(메일 링크는 확인 화면을 열고 화면이 POST) `가안` | 로그인 필요 | 메일에서 한 번에 끌 수 있어야 한다(N-18). GET 한 번으로 끄면 메일 미리보기 로봇이 눌러 버린다 |
| D-8 | 받아 보는 글 탭 | 첫 화면 글 모음과 같은 카드, `GET /api/v1/me/subscriptions/feed?page=` `가안` | 따로 화면 | 이미 있는 카드·페이지 번호를 그대로 쓴다 |
| D-9 | 모양 | 단추 "원고 받아 보기 / 받아 보는 중", 우편함 소식마다 우표(새 글은 "원고", 댓글은 "답장"), 안 읽은 것은 우표에 소인이 없음 `가안` | 종 아이콘 | 글결의 원고지·우편 콘셉트로 다른 블로그와 다르게 |
